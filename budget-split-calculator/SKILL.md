# budget-split-calculator

把一笔钱拆分到各个类别上。流程分三个阶段：收集信息、确认总额分配、输出明细。每个阶段都要等我回应后再进入下一个阶段。

## 阶段 1：先问

先问我这三项：

1. 总预算（或收入）是多少，周期是什么（一次性、每月、每周），币种是什么
2. 有哪些固定的必须支出，每项多少钱（如房租、还款、保险、交通）
3. 想把钱分到哪些类别或目标上，哪些优先级最高（如储蓄、娱乐、学习），有没有指定金额或比例

规则：

- 这三项没问清楚之前，不要开始计算。
- 问完就停下，等我回答。不要在同一条消息里给出任何分配结果。
- 我的回答含糊时（如「一点」「大概」「差不多」），针对缺失的数字追问，不要自己估一个。
- 可以附带问一句：是否指定分配方法（50/30/20、零基预算、信封法、自定义比例）。这一项不阻塞流程。我没指定时，默认用零基预算，并在结果里说明用了什么方法。

## 阶段 2：计算并给出总额分配（等我确认）

### 步骤

1. **列出**总预算、固定支出和我想分配的类别。
2. **先扣固定支出，再分配剩余**。可支配金额 = 总预算 − 固定支出合计。
3. **按优先级分配**。优先级越高、越刚性的类别，越先保障、占比越大。
   - 我指定了金额或比例的类别，先按我指定的满足。
   - 剩余金额按优先级权重分给其他类别。我没给权重时，用 高:中:低 = 3:2:1，并在表里写明，方便我调整。
   - 遵守我给的每个类别的上限和下限。
4. **预留应急缓冲**，不得分配掉。默认取可支配金额的 5%。我提到收入不稳定或支出波动大时取 10%。我也可以指定比例。每次都写明所用比例。
5. **总额校验**。固定支出 + 各类别 + 应急缓冲 + 余数 = 总预算，不一致就重新计算，不要带着差额输出。

### 用脚本计算（必须）

所有金额计算都交给 `scripts/budget_calc.py`，不要心算。步骤：

1. 把我给的数字写成 JSON 文件，字段见 `references/input-example.json`。文件放在系统临时目录，如 `$env:TEMP\budget-input.json`。
2. 运行（第一段让 PowerShell 按 UTF-8 读脚本输出，否则中文会乱码）：
   ```
   [Console]::OutputEncoding = [Text.Encoding]::UTF8; uv run <本 Skill 目录>/scripts/budget_calc.py allocate $env:TEMP\budget-input.json
   ```
   如果 shell 找不到 `uv`，改用完整路径：`$env:LOCALAPPDATA\Microsoft\WinGet\Packages\astral-sh.uv_Microsoft.Winget.Source_8wekyb3d8bbwe\uv.exe`。
3. 脚本输出的表格就是阶段 2 的分配表，直接引用，不要改动数字。
4. 退出码 0 表示成功。退出码 1 表示预算不足或条件冲突，脚本只输出缺口和取舍方向，不做分配，此时按下面「计算约束」的最后一条处理。退出码 2 表示输入有误，根据错误信息向我追问。
5. 脚本输出里的「注意」行（如没给优先级、因上限没分完）要原样告诉我，由我决定怎么处理。

脚本能做的事：

- 加权分配时遵守每个类别的 `min` 和 `max`，触及上限或下限后，多出或不足的金额自动在其他类别间重新分配。
- 支持指定金额（`amount`）或指定比例（`percent`，20 表示总预算的 20%）。
- 支持有小数的币种，把 `step` 设为 `0.01`。
- `--format json` 输出结构化结果，`--csv 路径` 导出 CSV（Excel 可直接打开，不会覆盖已有文件，需覆盖时加 `--overwrite`）。
- 要对比两套方案时，用两份不同的输入各跑一次。

### 计算约束

- 金额取整到币种常用的最小单位（人民币默认到元）。取整产生的差额放进单独的「余数」行，不要悄悄塞进某个类别。
- 占比一律以总预算为分母。
- 固定支出合计已经超过总预算，或我指定的金额加缓冲超过可支配金额时，不要自行缩减任何一项。只列出缺口金额和几种取舍选项（降低某个类别、减少缓冲、增加预算、调整固定支出），停下来让我选。

### 输出格式

一张表，列为：类别、金额、占比、备注。

- 行：固定支出（逐项）、各目标类别、应急缓冲、余数。
- 备注写依据，如「固定支出」「我指定的比例」「按优先级 3:2:1 分配」「缓冲 5%」。
- 表末附合计行，以及校验结果（合计是否等于总预算）。
- 表前用一行写明所用分配方法。

我要求对比时，另给出 2 套方案（如偏储蓄、偏均衡），每套一张同格式的表，并列出两套之间的主要差异。由我来选，不要替我选。

表后用一句话请我确认，然后停下。**我确认之前，不要输出明细。**

## 阶段 3：输出明细

我确认后才进入这一阶段。

- 我没说拆分方式时，先问：按周、按子项还是按日。
- 明细表沿用四列（类别、金额、占比、备注）。按周或按日拆分时，在最前面加一列「周期」。
- 每个类别下各子项或各周期的金额之和，必须等于阶段 2 里确认的类别金额。明细表末尾同样附合计行和校验结果。
- 拆分用脚本的 `split` 子命令，保证合计精确：
  ```
  [Console]::OutputEncoding = [Text.Encoding]::UTF8; uv run <本 Skill 目录>/scripts/budget_calc.py split --amount 1918 --labels 第1周,第2周,第3周,第4周
  ```
  不给 `--weights` 时等分，取整补差的那一份会在备注里标明。各子项权重不同时，用 `--weights 3,2,1,1`。
- 明细不得改动已确认的类别总额。我想改总额时，回到阶段 2 重新确认。

## 可选扩展：MCP 工具

下面两个 MCP 服务配置好之后才可用，配置内容见 `references/mcp-config.json`。工具不在当前可用列表里时，不要假装能用，直接按「没有 MCP」的做法处理。

**汇率（`frankfurter-fx`）**：预算涉及多个币种时使用，如旅行预算。

- 先用 `get_latest_exchange_rates` 或 `convert_currency_latest` 查汇率，再把换算后的金额填进输入 JSON。
- 工具返回的金额可能带浮点尾数（如 `1675.8400000000001`）。填入前四舍五入到分，金额写成字符串（如 `"2513.76"`），并把输入里的 `step` 设为 `"0.01"`。不这样做，脚本会以退出码 2 拒绝带小数的金额。
- 把原币种金额和换算过程写进名称或备注，如「酒店（60000 JPY，汇率 0.041896，2026-11-24）」。
- 结果里写明汇率数值、查询日期和来源（Frankfurter，欧洲央行等机构发布的参考汇率）。提醒我银行或支付渠道的实际汇率和手续费会有差异。
- 没有这个工具时，请我提供汇率，不要凭记忆写。

**Excel 导出（`excel`）**：我要求导出表格时使用。

- 文件只能放在 `C:\Users\Jason\Desktop\Kiro\budgets`，不要覆盖已有文件，同名时换一个文件名并告诉我。
- 导出前先问我文件名。内容用脚本算出的数字，不要重新计算。
- 没有这个工具时，改用脚本的 `--csv` 导出，Excel 同样能打开。

## 不做

- 不编造收入、价格、汇率或我没给过的数字，缺什么就问。汇率只用我提供的，或从汇率工具查到并标明日期的。
- 不让分配总额超过总预算。
- 不替我决定砍掉哪个类别或目标。预算不够时，只列缺口和取舍选项，让我来选。
- 不推荐具体的理财或投资产品。
